## What each phase delivered

- **Phase 0/1 — documents:** node tree (incl. table/image blocks),
  operations, snapshot undo/redo, comments, track-change suggestions,
  deterministic JSON, SQLite store, Markdown + HTML export, DOCX
  export/import with byte-stable round-trip on the fixture.
- **Phase 2 — Rust:** `rust/doc_core` mirrors the Dart model; golden
  vectors generated by the real Dart engine; JSON re-serialization and
  Markdown export are byte-identical between Dart and Rust.
- **Phase 3 — sync:** RGA text CRDT (Lamport counters, tombstones,
  convergence property tests), document deltas, field-level merge with
  conflict copies (zero data loss asserted), resumable/cancellable
  push-pull sessions vs an in-memory server.
- **Phase 4 — presentations:** scene graph, animation tracks, easings,
  pure `stateAt` playback core (golden RenderState), transitions incl.
  magic move, presenter model.
- **Phase 5 — sheets:** formula tokenizer/AST/evaluator (33 functions),
  dependency graph with incremental recalc and `#CYCLE!` detection,
  charts data, pivot summaries, CSV/JSON; 5,000-cell chain test.
- **Phase 6 — PDF:** from-scratch deterministic PDF 1.7 writer (xref
  offsets asserted correct), A4 layout, annotations, structured mode
  and PDF/A-mode structures (NOT certified — see ACCEPTANCE.md).
- **Phase 7 — API + MCP:** provider-agnostic adapter (complete/stream,
  typed errors, secret redaction proven by tests) against local mock
  servers; MCP server + client with all seven API_MCP.md tools,
  per-tool permissions, session token, append-only audit log.
- **Phase 8 — hardening:** AES-256-GCM `EncryptedDocumentStore`
  (cryptography 2.9.0; plaintext absent at rest, tamper/wrong-key
  tests), security scan script (negative-tested).
